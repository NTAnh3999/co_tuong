# Brief: T0.2 — pnpm workspace scaffold

## Goal

Create the pnpm + Turborepo monorepo skeleton for this project: root tooling config, workspace definition, and empty-but-buildable package skeletons for 5 packages/services. `apps/web` and `apps/api` are separate tasks (T0.3/T0.4) — do not create them, but your `pnpm-workspace.yaml` and `turbo.json` must already account for an `apps/*` glob so they drop in without edits later.

## Acceptance-criteria IDs

None directly (infra enabler). Gate is: `pnpm install` succeeds, `pnpm turbo run build lint typecheck test` succeeds across all created packages.

## Forbidden

- Do not create `apps/web` or `apps/api` (separate tasks).
- Do not run `pnpm install` yourself if it requires network access — attempt it, and if it fails because the sandbox has no network, say so in KNOWN GAPS; the orchestrator will run the install and report back. (You may still write the full lockfile-free scaffold.)
- Do not write to any dot-prefixed directory other than the ones explicitly listed above (`.gitignore`, `.nvmrc`, `.editorconfig` are dot-FILES at root, which is fine).

## Conventions (from root AGENTS.md — read that file too)

- Package scope `@xq/*`, e.g. `@xq/xiangqi-core`, `@xq/shared-contracts`, `@xq/api-client`, `@xq/content`. The pikafish worker is a standalone service, name it `@xq/pikafish-worker` but it's run as a service, not imported — still give it the same package shape for tooling consistency.
- Node engines: `>=22`. Root `package.json` needs `"packageManager": "pnpm@<version you have installed — check with `pnpm --version`, pin exactly>"` and `"engines": {"node": ">=22"}`.
- Each of the 5 packages: dual ESM+CJS build via `tsup` (preferred — simple config, builds both `dist/index.mjs` and `dist/index.cjs` plus `.d.ts`), with `package.json` `exports` map pointing both conditions correctly (`"import"`, `"require"`, `"types"`). TypeScript strict mode via `tsconfig.base.json` extended by each package's own `tsconfig.json`.
- `tsconfig.base.json` must set: `"strict": true`, `"noUncheckedIndexedAccess": true`, `"verbatimModuleSyntax": true`, `"target": "ES2022"`, `"module": "NodeNext"`, `"moduleResolution": "NodeNext"`, `"skipLibCheck": true`, `"esModuleInterop": true`, `"forceConsistentCasingInFileNames": true`, `"declaration": true`.
- `turbo.json`: pipeline tasks `build` (depends on `^build`, outputs `dist/**`), `test`, `typecheck`, `lint`, and a persistent `dev` task (no cache, persistent: true). Use Turborepo's current config key (`tasks`, not the older `pipeline` key — check your `turbo` version's docs if unsure, but `tasks` is correct for Turbo 2.x).
- Each package gets Vitest configured (`vitest.config.ts` or config in `package.json`) with exactly one placeholder test that imports the package's own `index.ts` and asserts it's truthy/defined — just enough to prove the build+test pipeline works end-to-end. Real content comes in M1/M3/M5/M6.
- `pnpm-workspace.yaml` packages: `apps/*`, `packages/*`, `services/*`.
