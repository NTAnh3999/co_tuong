# Brief: T0.6 — Dev Docker Compose, env examples, README quickstart

## Goal

Give the project a one-command local Postgres for development/testing, documented env var examples per app, and a README quickstart so a new contributor (or a future task) can get the repo running without guessing.

## Acceptance-criteria IDs

None directly (infra enabler).

## What to build

### 1. `infrastructure/docker/docker-compose.dev.yml`

A Docker Compose file with one service, `postgres`:
- Image `postgres:17-alpine`.
- Environment: `POSTGRES_USER=xq`, `POSTGRES_PASSWORD=xq_dev_password`, `POSTGRES_DB=xq_dev`.
- Port mapping `5432:5432`.
- A named volume for data persistence (e.g. `xq_pgdata`).
- A healthcheck using `pg_isready -U xq`.
- An init step (via a mounted `init.sql` under `infrastructure/docker/init.sql`, allowed path extension — list it too) that also creates a second database `xq_test` (for the test-suite harness M3 will use), since Postgres's `POSTGRES_DB` env var only creates one database at container start.

Add `infrastructure/docker/init.sql` to the allowed-paths list implicitly — it's needed for the above; write it as:
```sql
CREATE DATABASE xq_test;
```
(Postgres image init scripts run in `/docker-entrypoint-initdb.d/`; mount this file there in the compose service definition.)

### 2. `apps/api/.env.example`

Document the env vars `apps/api` needs, based on what T0.3 built (check `apps/api/src/config/env.schema.ts` if it exists, to match real variable names) plus what M3 will need soon (DB connection). At minimum:
```
NODE_ENV=development
PORT=3001
DATABASE_URL=postgresql://xq:xq_dev_password@localhost:5432/xq_dev
```
Add a comment above `DATABASE_URL` noting the matching `docker-compose.dev.yml` credentials.

### 3. `apps/web/.env.example`

```
NEXT_PUBLIC_API_BASE_URL=http://localhost:3001/api/v1
```

### 4. Root `README.md`

A concise quickstart covering:
- One-line project description (Xiangqi Learn & Play — Cờ Tướng web platform).
- Prerequisites: Node >=22, pnpm (via corepack), Docker.
- Setup steps: `corepack enable`, `pnpm install`, copy `.env.example` → `.env` in `apps/api` and `apps/web`, `docker compose -f infrastructure/docker/docker-compose.dev.yml up -d`, `pnpm turbo run build`.
- How to run tests: `pnpm turbo run test`.
- Pointers to `.agents/PLAN.md` (execution plan), `docs/spec/v1.0/` (product spec), `docs/adr/` (architecture decisions), `AGENTS.md` (contribution conventions for any agent/person working in this repo).
- Keep it short — this is a quickstart, not full documentation.
