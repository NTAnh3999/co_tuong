# Brief: T1.2 — Pseudo-legal move generation (all 7 pieces) + attack detection

## Goal

Implement pseudo-legal move generation for every piece type, plus a square-attack query used later for check detection. "Pseudo-legal" means: obeys each piece's own movement/blocking rules and board bounds, but does **not yet** check whether the move leaves the mover's own General in check, and does **not** implement the "flying general" (facing-generals) prohibition — both of those are T1.3's job (the legality filter layered on top of this).

## Acceptance-criteria IDs

CORE-02 (per-piece movement correctness)

## Allowed paths

- `packages/xiangqi-core/src/**` (new files alongside T1.1's `square.ts`/`types.ts`/`position.ts`/`fen.ts`/`move.ts` — do not modify those files' public behavior, only import from them)
- `packages/xiangqi-core/src/index.ts` (extend exports)

## Forbidden

- Do not implement `isInCheck`, `getLegalMoves`, `isLegalMove`, or `applyMove` — those are T1.3. This task only produces pseudo-legal move lists and an attack query.
- Do not add runtime dependencies (stays pure TypeScript, per `packages/xiangqi-core/AGENTS.md`).

## Board geometry recap (from ADR-018 — files a-i = 0-8, ranks 0-9, Red's back rank = 0)

- **Palace**: files `d`-`f` (file index 3-5). Red's palace is ranks 0-2. Black's palace is ranks 7-9.
- **River**: the boundary between rank 4 and rank 5. Red's own half is ranks 0-4; Black's own half is ranks 5-9.

## Required API

```ts
// Generates every pseudo-legal destination for the piece sitting on `square`,
// based on THAT PIECE's OWN color (not necessarily position.turn — this must
// work for either side regardless of whose turn it is, since attack detection
// in T1.3 needs to compute the opponent's pseudo-legal/attacking moves too).
// Returns [] if `square` is empty.
function getPseudoLegalMoves(position: Position, square: Square): Move[];

// All pseudo-legal moves for every piece belonging to `color`.
function getAllPseudoLegalMoves(position: Position, color: Color): Move[];

// True if any piece of `byColor` could capture/land on `square` on its next
// move, using each piece's CAPTURING pattern specifically (see Cannon note
// below — its capture pattern differs from its non-capturing slide).
// Does NOT include the flying-general special case (that's T1.3's concern).
function isSquareAttacked(position: Position, square: Square, byColor: Color): boolean;
```

Pick ONE clear pattern (e.g. `src/pieces/<piece>.ts` + `src/pieces/<piece>.test.ts`) and state it explicitly in your final message so the next task can follow it exactly.

## Exact movement rules per piece

### GENERAL (Tướng/Tư)
Moves exactly one step orthogonally (up/down/left/right, never diagonal). Destination must stay inside the mover's own palace (file 3-5, rank 0-2 for Red / rank 7-9 for Black).

### ADVISOR (Sĩ)
Moves exactly one step diagonally. Destination must stay inside the mover's own palace. (Combined with the one-diagonal-step rule, an Advisor can only ever occupy 5 squares total within its palace — the center and the four corners.)

### ELEPHANT (Tượng)
Moves exactly two points diagonally (e.g. `(file, rank)` → `(file±2, rank±2)`). Two blocking/restriction rules, BOTH required:
1. **Eye-blocking**: the single square at the diagonal midpoint (`(file±1, rank±1)`) must be empty, or the move is illegal — "bị cản mắt".
2. **River restriction**: the Elephant may never cross the river. Red's Elephant destinations must have rank ≤ 4; Black's must have rank ≥ 5.
(Elephants start on their own half and these two rules together naturally keep them there — your implementation should still check both explicitly rather than relying on starting position alone, since this function must be correct for arbitrary positions, not just the opening.)

### HORSE (Mã)
Moves in an L-shape: one step orthogonal plus one step diagonal continuing outward, i.e. total displacement `(±1, ±2)` or `(±2, ±1)`. Blocked by the "leg" — the orthogonally-adjacent square in the direction of the move's LONGER axis:
- For a `(±1, ±2)` move (rank changes by 2, file by 1): the leg is at `(file, rank + sign(Δrank))` — one step in the rank direction, same file.
- For a `(±2, ±1)` move (file changes by 2, rank by 1): the leg is at `(file + sign(Δfile), rank)` — one step in the file direction, same rank.
If the leg square is occupied (by either color), that specific destination is blocked — "bị cản chân". Check each of the 8 possible destinations independently; a Horse can have between 0 and 8 pseudo-legal destinations depending on board edges and blocking.

### CHARIOT (Xe)
Slides any number of squares orthogonally (like a chess Rook), stopping at the first occupied square. If that first occupied square holds an enemy piece, it's a valid capturing destination; if it holds a friendly piece, it is NOT a valid destination and the slide stops before it. No jumping.

### CANNON (Pháo)
Two distinct movement modes along the same four orthogonal rays:
1. **Non-capturing move**: slides like a Chariot to any empty square along the ray, stopping before the first occupied square (cannot land on or capture on this mode).
2. **Capturing move**: along the ray, there must be exactly one piece (either color) acting as a "screen" between the Cannon and the target square, and the target square must hold an enemy piece. The Cannon jumps over exactly that one screen piece and captures the enemy piece on the far side. If there are zero screens before the first piece, it's just a blocked slide (covered by mode 1, can't capture adjacent-without-jump). If there are two or more pieces before reaching an enemy piece, it cannot capture that far piece (only the first piece beyond exactly one screen is reachable).
This matters for `isSquareAttacked`: a Cannon's "attacking" squares use mode 2's pattern (through exactly one screen), NOT mode 1's slide pattern — a Cannon threatens a square it could *capture into*, not every empty square it could slide to.

### SOLDIER (Tốt/Binh)
Direction of "forward" depends on color: Red moves toward increasing rank (from rank 0 toward rank 9); Black moves toward decreasing rank (from rank 9 toward rank 0).
- **Before crossing the river** (Red: rank ≤ 4; Black: rank ≥ 5): may only move one step forward (never sideways, never backward).
- **After crossing the river** (Red: rank ≥ 5; Black: rank ≤ 4): may move one step forward, or one step sideways (file ±1, same rank) — but still NEVER backward.
A Soldier's capture pattern is identical to its move pattern (no diagonal-capture distinction like international chess pawns) — whatever squares it can move to, it can also capture an enemy piece on, same rule.

## Required tests

Put per-piece tests under whatever file pattern you chose (state it in your final message). Title prefix `CORE-02: <piece> ...`. Cover, at minimum, for EACH of the 7 piece types: a basic unobstructed-move case, an edge-of-board/edge-of-palace/edge-of-river boundary case, and a blocked case (friendly piece, enemy piece, or the specific leg/eye-blocker for Horse/Elephant).
