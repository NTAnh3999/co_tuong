## The "flying general" rule — model it AS a form of check, don't special-case it separately

This is the key design insight that keeps the legality filter simple and correct: define `isInCheck(position, color)` to return true if **either**:
1. The `color` General's square is attacked by the opponent, per T1.2's `isSquareAttacked(position, generalSquare, opponentColor)`, **or**
2. The two Generals are on the same file with no piece of any kind between them (the "flying general" / facing-generals condition) — in this case, treat `color`'s General as being in check by the opponent's General directly.

With this definition, the ordinary legality filter ("a move is illegal if it leaves your own General in check") **automatically** also forbids ending up in a facing-generals position — you don't need a second, separate special case anywhere else in the legality filter. This matches the real rule exactly: facing generals is illegal for whichever side's move just created that board state, symmetric to how leaving your own General attacked is illegal.

Implementation approach: find each color's General square (scan the board for `type === 'GENERAL'`; if a color has zero or more than one General, that's a malformed position — throw a clear error, since this should never happen for any position produced by legal play from `createInitialPosition()` or a validated `fromFen` result). If both Generals share the same file (same `file` component of their square index) and every square strictly between them on that file is empty, condition 2 is true.

## Required API

```ts
// True if `color`'s General is in check (per the combined definition above).
function isInCheck(position: Position, color: Color): boolean;

// Pseudo-legal moves from `square`, filtered to exclude any that leave the
// MOVING PIECE'S OWN color in check (including the flying-general case).
// Does not check whose turn it is — purely "if this piece moved like this,
// would its own side end up in/remain in check".
function getLegalMoves(position: Position, square: Square): Move[];

// All legal moves for every piece belonging to `color`.
function getAllLegalMoves(position: Position, color: Color): Move[];

// True if `move` is legal to play RIGHT NOW: there must be a piece at
// `move.from` belonging to `position.turn` (not just any color), the move
// must be among that piece's pseudo-legal moves, and it must not leave
// position.turn's own General in check afterward.
function isLegalMove(position: Position, move: Move): boolean;

// Pure function: returns a NEW Position with the move applied. Must NOT
// mutate the input `position` object or its `board` array in any way
// (tests will deep-freeze the input and fail on any mutation attempt).
// Does NOT validate legality — assumes the caller already knows the move
// is at least structurally sane (a piece exists at `move.from`); throws a
// clear error only if `move.from` is empty (nothing to move). Behavior:
//  - Remove whatever piece is at `move.from` from its square.
//  - If `move.to` holds a piece (of either color — capturing your own
//    piece is a caller error, not this function's job to prevent), it is
//    replaced by the moving piece.
//  - halfmoveClock: reset to 0 if this move captured a piece, otherwise
//    the old value + 1.
//  - turn: flips to the other color.
//  - fullmoveNumber: increments by 1 only when BLACK just moved (i.e. when
//    the position's turn BEFORE this move was 'black') — standard FEN
//    convention, matches Pikafish.
function applyMove(position: Position, move: Move): Position;

// Total leaf-node count after `depth` plies of EVERY legal move at each
// level (standard chess-engine "perft"), starting from position.turn.
// perft(position, 0) === 1. perft(position, 1) === getAllLegalMoves(position, position.turn).length.
function perft(position: Position, depth: number): number;

// Like perft, but returns the per-ROOT-move breakdown: for each legal move
// available right now, how many leaf nodes are under it at `depth - 1`
// plies beyond that move. Keys are UCI move strings via `encodeMove`.
// This exact shape matches `packages/xiangqi-core/fixtures/schema.ts`'s
// `PositionFixture.perft` field and the golden fixture already generated
// at `packages/xiangqi-core/fixtures/golden/startpos.json` — your output
// for depth 1-3 from the start position MUST exactly match that file's
// `perft["1"]`, `perft["2"]`, `perft["3"]` entries (same move keys, same
// per-move counts, same totals). Check your implementation against that
// file directly as part of your own verification.
function divide(position: Position, depth: number): { moves: Record<string, number>; total: number };
```

## Implementation notes

- `getLegalMoves`/`getAllLegalMoves`/`isLegalMove` should all go through a common internal helper: for a candidate pseudo-legal move, call `applyMove` to get the resulting position, then check `!isInCheck(resultingPosition, movingPieceColor)` — keep the move only if that holds.
- For `perft`/`divide`, at each recursive level, use `getAllLegalMoves(position, position.turn)` (not a fixed color) — `position.turn` is already correct after each `applyMove` call since `applyMove` flips it.
- Performance isn't a concern for this task (no need for bitboards or move-ordering tricks) — straightforward recursive generate-and-apply is fine. Depth 3 from the start position should run in well under a second even with a naive implementation; depth 4 may take a few seconds, which is acceptable (T1.4/CI will gate depth-4 perft behind an opt-in flag, not run it by default).

## Required tests

Title prefix `CORE-03` for General-safety/legality tests, reuse `CORE-02` where testing legal-move filtering specifically relates to piece movement correctness interacting with check.

1. **Self-check prevention**: construct a position where moving a piece would expose the mover's own General to an attack (e.g. a pinned piece in front of the General on an open file, with an enemy Chariot beyond) — assert that move is excluded from `getLegalMoves` for that piece, even though it's pseudo-legal per T1.2.
2. **Must resolve existing check**: construct a position where `color`'s General is already in check — assert that `getAllLegalMoves(position, color)` only contains moves that resolve the check (capture the checking piece, block it, or move the General away), and moves that ignore the check are excluded.
3. **Flying general — moving a screen away is illegal**: two Generals on the same file with exactly one piece between them; moving that blocking piece away (when it belongs to the side whose move it is) must be excluded from legal moves, since it would expose the facing-generals condition. Verify via `isInCheck` directly too: after manually constructing the "generals facing, nothing between" position (bypass `getLegalMoves` and just build the `Position` by hand, as `moves.test.ts` does), `isInCheck` must return `true` for whichever color's turn it is in that fabricated position (or more precisely: test it both ways — `isInCheck(pos, 'red')` and `isInCheck(pos, 'black')` should both be `true` when the generals are facing with nothing between, since the condition is symmetric).
4. **Checkmate scenario**: a position where `color` is in check AND has zero legal moves — `getAllLegalMoves(position, color)` returns `[]`. (You don't need to classify this as "checkmate" vs "stalemate" here — that's T1.6's `evaluateGame` — just confirm the empty legal-move-list case works correctly when check is present.)
5. **`applyMove` purity**: deep-freeze a `Position` (`Object.freeze` the object AND the board array AND consider freezing each piece object too — use `structuredClone`-then-freeze or manual deep freeze) before calling `applyMove`; assert it doesn't throw (i.e. doesn't attempt a mutation) and that the original frozen object's contents are unchanged after the call.
6. **`applyMove` mechanics**: a non-capturing move increments `halfmoveClock`; a capturing move resets it to 0; `turn` flips; `fullmoveNumber` increments only after Black's move (test both a Red move, where it stays the same, and a Black move, where it increments).
7. **`perft`/`divide` against the golden fixture**: load `packages/xiangqi-core/fixtures/golden/startpos.json` (it's plain JSON — import/read it directly, e.g. via a relative `fs.readFileSync` + `JSON.parse`, or a JSON import if your TS/bundler config supports `resolveJsonModule`/`import ... with { type: 'json' }` — your call, whichever is simplest and works with the existing `tsconfig.json`/vitest setup) and assert your `divide(createInitialPosition(), 1)`, `divide(createInitialPosition(), 2)`, and `divide(createInitialPosition(), 3)` exactly match that file's `positions[0].perft["1"]`, `["2"]`, `["3"]` entries (both the per-move breakdown AND the total). **This is the single most important test in this task** — if it doesn't match exactly, something in T1.1/T1.2/T1.3 has a real bug, not a test-writing issue; debug until it matches exactly, don't adjust the fixture (the fixture was generated by the real Pikafish binary, it's ground truth).
