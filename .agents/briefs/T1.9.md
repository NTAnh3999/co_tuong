## What to do

### 1. Audit `src/index.ts`

Confirm every public type and function from T1.1-T1.8 is actually exported and reachable by a consumer importing `@xq/xiangqi-core`: `Square`, `Color`, `PieceType`, `Piece`, `Position`, `Move`, `toSquare`, `squareToIndex`, `indexToSquare`, `createInitialPosition`, `toFen`, `fromFen`, `encodeMove`, `decodeMove`, `getPseudoLegalMoves`, `getAllPseudoLegalMoves`, `isSquareAttacked`, `isInCheck`, `getLegalMoves`, `getAllLegalMoves`, `isLegalMove`, `applyMove`, `perft`, `divide`, `ResultReason`, `GameResult`, `TerminalEvent`, `GameRecord`, `ReplayStep`, `RuleSet`, `CASUAL_RULESET`, `positionKey`, `replay`, `evaluateGame`. If anything is missing from the export list, add it. If you find a naming inconsistency or something that looks unintentionally missing, note it in KNOWN GAPS rather than silently renaming anything (renaming is a breaking change for later tasks that may already reference the current names).

### 2. TSDoc comments

Add a one-to-three-sentence `/** ... */` TSDoc comment above each exported function and interface/type across `src/*.ts`, explaining what it does and any non-obvious contract detail (e.g. "pure, does not mutate its input", "throws if X", "uses ADR-018's coordinate convention"). Keep these SHORT — this is reference documentation, not a tutorial. Many functions may already have a one-line comment from earlier tasks; expand only where it's genuinely thin, don't rewrite comments that are already adequate.

### 3. `README.md`

A concise package README covering:
- One-sentence description: a pure TypeScript Xiangqi (Chinese Chess) rules engine, no UI/DOM/network/database dependencies.
- Install/usage: `import { createInitialPosition, getLegalMoves, applyMove, ... } from '@xq/xiangqi-core'`.
- A short "quick example" code block: create the initial position, get legal moves for a square, apply a move, check the result.
- A short explanation of the coordinate/FEN convention (link to `docs/adr/ADR-018-coordinates-fen-uci.md` rather than re-explaining it in full).
- A short explanation that game-ending rules follow the casual ruleset in `docs/adr/ADR-017-ruleset-casual-v1.md`, NOT official AXF competitive rules, and that perpetual chase is not implemented.
- A one-line note on the test suite composition (unit, oracle-verified fixtures against the real Pikafish engine, property-based tests).

### 4. Coverage thresholds

Add a `coverage` block to `packages/xiangqi-core/vitest.config.ts` using `@vitest/coverage-v8` (already installed) with thresholds: **90% lines, 85% branches** (statements/functions can follow whichever of those two numbers is more appropriate for this codebase — your call, but don't set them so loose that they're meaningless). Add a `"test:coverage": "vitest run --coverage"` script to `package.json`. Actually RUN it and confirm the current test suite (T1.1-T1.8's combined output) meets the thresholds — if it doesn't, do NOT lower the thresholds to make it pass; instead report exactly which file/lines are under-covered in KNOWN GAPS/QUESTIONS so a follow-up task can add the missing test coverage (you are not adding new tests in this task, that's out of scope — T1.5/T1.7/T1.8 already did the heavy lifting; this task just wires up and reports on the threshold check).
