# Brief: T2.1 — GameController contract + LocalGameController

## Goal

Define the `GameController` interface that EVERY game mode (local, online, AI, puzzle, replay) will implement, and build the first concrete implementation: `LocalGameController` for two people sharing one device. This is the seam between `xiangqi-core` (pure rules) and any UI — the renderer (`Board2D`, built in T2.2) only ever talks to a `GameController`, never to `xiangqi-core` directly.

## Design

Use `zustand/vanilla`'s `createStore` so the controller works identically in tests (no React needed) and from a React component later (via `zustand/react`'s `useStore(store)` — that wiring happens in T2.4, not here).

```ts
import type { Color, GameResult, Move, Position, Square } from '@xq/xiangqi-core';

export interface GameControllerState {
  readonly position: Position;
  readonly history: readonly Move[];
  readonly lastMove: Move | null;
  readonly selectedSquare: Square | null;
  readonly legalTargets: readonly Square[]; // legal destination squares for `selectedSquare`, [] if nothing selected
  readonly orientation: Color; // which color's palace is drawn at the bottom
  readonly result: GameResult | null; // null while the game is ongoing
}

export interface GameController {
  getState(): GameControllerState;
  subscribe(listener: () => void): () => void; // returns an unsubscribe function
  /** Click/tap handling: see the state machine below. Pass `null` to deselect. */
  selectSquare(square: Square | null): void;
  /** Direct move submission (e.g. drag-and-drop, or programmatic use in tests).
   *  Returns true if the move was legal and applied, false if rejected. Does
   *  nothing to `selectedSquare`/`legalTargets` beyond clearing them on success. */
  submitMove(move: Move): boolean;
  /** Toggles which color's side is drawn at the bottom. Pure rendering concern. */
  flip(): void;
  /** Optional capabilities — present on LocalGameController, may not be on every mode. */
  resign?(color: Color): void;
  undo?(): void;
  offerDraw?(): void;
}
```

### `selectSquare` state machine

- `square === null`: clear `selectedSquare`/`legalTargets`.
- Nothing currently selected:
  - If `square` holds a piece belonging to `state.position.turn`: select it — set `selectedSquare = square`, `legalTargets = getLegalMoves(position, square).map(m => m.to)`.
  - Otherwise: no-op.
- Something IS currently selected:
  - If `square` is in `legalTargets`: this is the second tap of a tap-to-tap move — call the same internal apply-move logic `submitMove` uses, for `{ from: selectedSquare, to: square }`, then clear selection regardless of outcome.
  - Else if `square` holds a different piece belonging to `state.position.turn`: switch the selection to it (same as the "nothing selected" branch).
  - Else: clear selection (clicked an irrelevant empty/enemy square).
- If `state.result !== null` (game already over): `selectSquare` and `submitMove` are both no-ops — no further moves accepted.

### Applying a move (shared by `submitMove` and the tap-to-tap path)

1. Validate with `isLegalMove(position, move)` from `@xq/xiangqi-core` — reject (return `false`) if not legal.
2. `position = applyMove(position, move)`, `history = [...history, move]`, `lastMove = move`.
3. Recompute `result` via `evaluateGame({ initialFen: <the game's starting FEN>, moves: history, ruleSetVersion: CASUAL_RULESET.version }, CASUAL_RULESET)` (import `CASUAL_RULESET` from `@xq/xiangqi-core`). Store the starting FEN once at controller creation, not derived from `position` each time.
4. Clear `selectedSquare`/`legalTargets`.
5. Notify subscribers.

### `LocalGameController` specifics

```ts
export function createLocalGameController(initialFen?: string): GameController;
```
Defaults `initialFen` to the standard starting position (`toFen(createInitialPosition())`) if omitted. Implements `resign(color)` (sets an internal `terminalEvent: { type: 'RESIGNATION', loser: color }` and recomputes `result` via `evaluateGame` with that event — note `evaluateGame` only uses a record's `terminalEvent` when no board-derived rule already applies, so a resignation in an otherwise-ongoing game works, but calling it when the game already ended some other way has no effect since `result` is already set from the board-derived path), `undo()` (pop the last move from `history`, replay from `initialFen` through the remaining history to recompute `position`/`lastMove`/`result`; no-op if `history` is empty; clears any `terminalEvent` set by a prior resign/draw since undo returns to a prior, presumably-ongoing state — think through whether this needs tracking a separate "pending terminal event" vs relying on re-running replay, and implement whichever is cleanest), and `offerDraw()` (for a LOCAL game sharing one device, there's no real negotiation — immediately end the game with `{ type: 'DRAW_AGREEMENT' }`, following the same evaluateGame recomputation path as resign).

## Required tests

Put these in `local-game-controller.test.ts` (DOM-free — these must run under plain Vitest with no `jsdom` environment needed, proving the controller truly has no UI dependency).

- Initial state: starting position, `history: []`, `result: null`, `orientation: 'red'` (default).
- `selectSquare` on an own-side piece populates `legalTargets` matching `getLegalMoves` directly.
- `selectSquare` on an empty/enemy square with nothing selected is a no-op.
- Tap-to-tap: select a piece, then tap one of its legal targets — move is applied, selection clears, `history`/`lastMove`/`position` update correctly.
- Tap-to-tap: select a piece, then tap a DIFFERENT own piece — selection switches, doesn't apply any move.
- `submitMove` with a legal move applies it and returns `true`; with an illegal move, returns `false` and changes nothing.
- A full short game reaching checkmate (reuse/adapt a mate sequence — you can construct one with `getAllLegalMoves`/`applyMove` directly in the test, or hand-derive one, your call) ends with `result` set correctly, and `submitMove`/`selectSquare` become no-ops afterward.
- `flip()` toggles `orientation` between `'red'` and `'black'` and back.
- `resign(color)` sets the correct `winner`/`reason: 'RESIGNATION'`.
- `offerDraw()` sets `reason: 'DRAW_AGREEMENT'`, `winner: null`.
- `undo()`: play 2-3 moves, undo once, confirm `position`/`history` match the state before the last move; undo on an empty history is a no-op; undo after a resign/draw returns to an ongoing (non-terminal) state (confirm `result` is `null` again, assuming the undo target itself isn't independently terminal).
- `subscribe`: a listener is called after a state-changing action, and NOT called after a no-op action (e.g. an illegal `submitMove`) — be precise about this, it matters for UI re-render efficiency later.
