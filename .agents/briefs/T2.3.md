# Brief: T2.3 — Game-page support components (MoveList, CapturedPieces, GameStatusBanner, ResultDialog)

## Goal

Build four small presentational React components that `/play/local` (T2.4) and later the online game page (T4.6) will assemble around `Board2D`. These components are pure display — they receive data via props and call callbacks, no `GameController`/`@xq/xiangqi-core` logic lives inside them beyond reading types.

## Acceptance-criteria IDs

None directly (supports LOCAL-01/WEB-01 via T2.4).

## Allowed paths

- `apps/web/src/features/game/components/**` (new — one file per component, e.g. `MoveList.tsx`, `CapturedPieces.tsx`, `GameStatusBanner.tsx`, `ResultDialog.tsx`, plus test files)

## Forbidden

- Do not modify `apps/web/src/features/game/board/**` (T2.2) or `apps/web/src/features/game/controller/**` (T2.1) — only import TYPES from `@xq/xiangqi-core` as needed.
- Do not build the `/play/local` page itself — that's T2.4.

## Components

### `MoveList`

```tsx
interface MoveListProps {
  readonly moves: readonly Move[]; // from GameControllerState.history
  readonly currentPly?: number; // highlight this ply if provided (used later by replay, T6.8 — optional, default: highlight the last move)
}
```
Render move pairs numbered like standard chess notation (`1. <red move> <black move>`, `2. ...`), using `encodeMove` (`@xq/xiangqi-core`) for each move's text (plain UCI text is fine, e.g. "h2e2" — a nicer traditional/WXF notation is a stretch task elsewhere, T2.7, not here). Scrollable list, most recent move visible by default.

### `CapturedPieces`

```tsx
interface CapturedPiecesProps {
  readonly captured: readonly Piece[]; // pieces captured so far, in order
  readonly color: Color; // show only the pieces OF this color that have been captured (i.e. "what Red has lost" vs "what Black has lost")
}
```
Small row of piece glyphs for the captured pieces of the given color. Reuse the SAME glyph mapping `Board2D` uses (`帥仕相馬車炮兵` / `將士象馬車砲卒`) — check `apps/web/src/features/game/board/Board2D.tsx` for its existing `PIECE_GLYPHS` map and import/reuse it (export it from `Board2D.tsx` if it isn't already exported) rather than redefining a second copy that could drift out of sync.

### `GameStatusBanner`

```tsx
interface GameStatusBannerProps {
  readonly turn: Color;
  readonly result: GameResult | null; // from GameControllerState.result
  readonly orientation: Color; // whose perspective this banner is shown from, if relevant to your copy (e.g. "Your turn" vs "Opponent's turn" — optional nuance, plain "Red to move"/"Black to move" is also fine)
}
```
A short status line: "Đỏ đi" / "Đen đi" (Vietnamese — this project's user-facing copy is Vietnamese per `AGENTS.md`) while `result` is `null`; once `result` is set, show the outcome in Vietnamese (e.g. "Đỏ thắng — Chiếu bí", "Hòa — Lặp thế") — map each `ResultReason` to a short Vietnamese label. You don't need a lookup table perfectly polished for every one of the 12 reasons from scratch — do your best with clear, short phrases; this is easy to refine later.

### `ResultDialog`

```tsx
interface ResultDialogProps {
  readonly result: GameResult | null; // dialog is open iff this is non-null
  readonly onRematch?: () => void;
  readonly onClose: () => void;
}
```
Uses the `Dialog` component from `apps/web/components/ui/dialog.tsx` (T0.4 — shadcn-style, already built). Shows the same outcome text as `GameStatusBanner` (reuse whatever mapping function you wrote for that, don't duplicate it — put the `ResultReason` → Vietnamese label mapping in one shared place both components import, e.g. `apps/web/src/features/game/components/result-text.ts`), plus a "Chơi lại" (rematch) button if `onRematch` is provided, and a close action using `Button` from `apps/web/components/ui/button.tsx`.

## Required tests

`@testing-library/react`, one test file per component (or combined, your call):
- `MoveList`: renders move pairs in the right numbered format for a short move list; empty list renders without crashing.
- `CapturedPieces`: filters to only the requested color; renders nothing (or an empty state) when nothing's captured yet.
- `GameStatusBanner`: shows the right text for `result: null` (ongoing) vs. at least 2-3 different `ResultReason` values.
- `ResultDialog`: not rendered/visible when `result` is `null`; visible with the right text when `result` is set; clicking rematch/close calls the right callback.
