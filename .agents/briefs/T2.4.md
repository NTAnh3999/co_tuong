## `/play` — mode picker

Per `docs/spec/v1.0/02_UX_Flows_Sitemap.md` §2.2: three mode cards/buttons — **Bạn bè** (online, → `/play/online`), **Đấu AI** (→ `/play/ai`), **Local** (→ `/play/local`). Use `Button`/card-style layout with the existing `Button` component (`apps/web/components/ui/button.tsx`). Simple, no data fetching needed.

## `/play/local` — the actual game

This page is a **Client Component** (`'use client'`) since it holds live interactive state. Structure:

1. Create a `LocalGameController` via `createLocalGameController()` (T2.1) — use `useRef` or `useState(() => createLocalGameController())` so exactly ONE controller instance persists across re-renders (not recreated every render).
2. Subscribe to the controller's state (T2.1's `subscribe`/`getState`) via a small custom hook, e.g. `useGameControllerState(controller)` implemented with `useSyncExternalStore` (React's purpose-built hook for exactly this external-store pattern — don't hand-roll `useEffect`+`useState` for this, `useSyncExternalStore` is the correct tool and avoids subtle tearing bugs).
3. Layout: `Board2D` (T2.2) as the centerpiece, fed `position`/`orientation`/`selectedSquare`/`legalTargets`/`lastMove` straight from the controller's state, `interactive={true}`, `onSquareClick={controller.selectSquare}`, `onMove={(move) => controller.submitMove(move)}`.
4. Side panel (desktop) / stacked section (mobile — simple responsive stacking is fine, doesn't need to be pixel-perfect): `GameStatusBanner`, `MoveList` (fed `state.history`), `CapturedPieces` for both colors (you'll need to derive "captured pieces" from the move history yourself — `GameControllerState` doesn't track this directly; compute it by diffing piece counts between the initial position and the current position, or by tracking captures as moves are replayed — your call on the simplest correct approach, e.g. replay `state.history` through `@xq/xiangqi-core`'s `applyMove` from the initial position while recording each step's captured piece, mirroring what `ReplayStep.captured` does in `game.ts` — you may need to do this replay yourself here since `LocalGameController`'s public state doesn't expose it; don't modify the controller to add it, compute it in the page).
5. Action buttons: "Đầu hàng" (resign) — needs to know WHICH color is resigning; since this is a shared-device local game, a simple approach is two buttons ("Đỏ đầu hàng" / "Đen đầu hàng") or a single button resigning whoever's turn it is — your call, document the choice. "Hòa" (offerDraw) — one button, immediate per T2.1's local semantics. "Ván mới" (new game) — recreate the controller (replace the ref/state with a fresh `createLocalGameController()` instance).
6. `ResultDialog` (T2.3), fed `state.result`, with `onRematch` wired to the same "new game" logic as above, `onClose` just closing the dialog (you'll need a small local `dismissed` boolean so closing doesn't just reopen on the next render — reset `dismissed` to `false` whenever a NEW game starts).
7. Flip button using `controller.flip()`.

## Required tests

- `/play`: renders the 3 mode links/buttons with correct `href`s.
- `/play/local`: renders the board with the starting position; clicking a piece then a legal destination (simulate via the same `fireEvent.pointerDown`/`pointerUp`-with-no-movement pattern `Board2D.test.tsx` already uses) actually moves a piece and updates `MoveList`; the resign button ends the game and opens `ResultDialog`; "Ván mới" resets back to the starting position.
