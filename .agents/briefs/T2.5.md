# Brief: T2.5 — Playwright E2E: a full local game to checkmate

## Goal

An end-to-end browser test that plays a REAL local game from the standard starting position all the way to checkmate, driving the actual rendered `/play/local` page (real clicks on real DOM elements, not calling any React/controller code directly), across all 3 configured Playwright projects (desktop-chromium, mobile-chrome, mobile-webkit — already set up in `apps/web/playwright.config.ts` from T0.4).

## Acceptance-criteria IDs

LOCAL-01, WEB-01

## Allowed paths

- `apps/web/e2e/**` (new spec file(s); `apps/web/e2e/smoke.spec.ts` already exists from T0.4 — don't modify it, add a new file)
- `apps/web/scripts/**` (a throwaway one-off Node script to DERIVE the mate sequence — see below; it does not need to be wired into any build/test pipeline, it's a tool you run once to produce the sequence, then hardcode the result)

## Forbidden

- Do not modify `apps/web/src/features/game/**` or `apps/web/app/play/**` (T2.1-T2.4, already built).
- Do not hand-write a "famous" mate sequence from memory — it must be derived and verified programmatically against `@xq/xiangqi-core`, since the whole point is catching a REAL bug in move generation/legality/checkmate detection, not testing against your own assumptions about what's legal.

## Step 1: derive a verified checkmate sequence (offline, not part of the test run)

Write a throwaway script (e.g. `apps/web/scripts/find-mate-sequence.ts`, run manually via `tsx` or `node --experimental-strip-types` — your call, doesn't need a package.json script entry since it's a one-off tool) that:
- Starts from `createInitialPosition()` (`@xq/xiangqi-core`).
- Searches for a sequence of LEGAL moves (via `getAllLegalMoves`/`applyMove`) that ends in checkmate — confirm the terminal position has ZERO legal moves for the side to move AND `isInCheck` is true for that side (i.e. genuinely `CHECKMATE`, not `STALEMATE`). A full from-scratch search for an optimal/fast mate is overkill — a reasonable approach: run many random-vs-random self-play games (same technique T1.4's oracle-fixture generator used) until one happens to terminate in checkmate within a manageable number of plies (aim for under ~40, but don't obsess over finding a SHORT mate — just a genuine, correctly-terminating one), and take that move sequence.
- Print the resulting move list (as UCI strings) to stdout.
- Run this yourself, capture the output, and hardcode the resulting move array as a constant directly in the E2E spec file (with a comment noting it was derived and verified by this script, and the exact command you ran). The script file itself can stay in the repo as a reproducibility record, or you can delete it after use — your call, but if you keep it, make sure it doesn't accidentally get picked up by any test runner glob (it shouldn't, `apps/web`'s test include patterns don't cover `scripts/`, but double check).

## Step 2: the E2E spec

`apps/web/e2e/local-game-checkmate.spec.ts`:
1. Navigate to `/play/local`.
2. For each move in the verified sequence: click the `from` square (via `page.locator('[data-square="<sq>"]')` — `Board2D` already renders this attribute, T2.2), then click the `to` square. (Tap-to-tap, matching `Board2D`'s interaction model — don't try to simulate drag-and-drop in Playwright for this test, clicking is simpler and sufficient.)
3. After the final move, assert the `ResultDialog` (T2.3) is visible and shows a checkmate-related result (check for whatever Vietnamese text `result-text.ts` produces for `CHECKMATE` — import/reference that mapping rather than hardcoding a potentially-stale duplicate of the Vietnamese string, or just assert on a stable `data-testid`/`role` if the dialog doesn't expose the exact text easily testable — your call on the most robust assertion).
4. Also assert the move list (`MoveList`, T2.3) shows the expected number of entries matching the sequence length.
5. This single spec runs automatically across all 3 configured Playwright projects (that's just how `playwright.config.ts`'s `projects` array works — you don't need to parametrize anything yourself, just write the one spec).

## Gate commands

```bash
pnpm --filter @xq/web exec playwright install --with-deps chromium webkit  # orchestrator will likely need to run this — browser binaries probably aren't available in your sandbox
pnpm --filter @xq/web test:e2e
```
Try running it yourself first. If Playwright's browser binaries aren't installed/installable in your sandbox (no network), note that clearly in KNOWN GAPS — the orchestrator will install them and run the suite. Still write and sanity-check the spec logically (e.g. mentally trace a couple of the clicks against what `Board2D`/`LocalGameController` do) even if you can't execute it end-to-end yourself.
