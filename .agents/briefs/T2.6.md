# Brief: T2.6 — App shell, nav, landing page, shared UX states

## Goal

Build the site-wide navigation shell and replace the T0.4 placeholder landing page with a real one, plus a small set of shared loading/empty/error/offline state components other pages (T2.4, T4.5, T4.6, M6) will reuse rather than each inventing their own.

## Acceptance-criteria IDs

None directly (supports WEB-01 broadly).

## Allowed paths

- `apps/web/app/layout.tsx` (extend — add the nav shell around `{children}`, keep the existing `<html>`/`<body>`/globals.css import)
- `apps/web/app/page.tsx` and `apps/web/app/page.test.tsx` (replace the placeholder landing content — you may remove the `coreStartingFen` interop-proof text now that `Board2D`/the controller already prove the core package resolves correctly elsewhere in the app; if you do, update/remove the corresponding assertion in `page.test.tsx`)
- `apps/web/src/components/shell/**` (new — nav bar, etc.)
- `apps/web/src/components/states/**` (new — loading/empty/error/offline components)

## Forbidden

- Do not build `/play`, `/play/local`, or any other route under `/play` — that's T2.4.
- Do not touch `apps/web/src/features/game/**` (T2.1/T2.2/T2.3).

## What to build

### Nav shell (`apps/web/src/components/shell/NavBar.tsx`, wired into `app/layout.tsx`)

Per `docs/spec/v1.0/02_UX_Flows_Sitemap.md` §1: 4 main nav items — **Trang chủ** (`/`), **Chơi** (`/play`), **Học** (`/learn`), **Cá nhân** (`/profile`). The latter three routes don't exist yet (T2.4, M6, M3-adjacent) — link to them anyway using Next's `Link` component; they'll 404 until those tasks land, which is fine and expected at this point. Keep the nav simple: logo/title text "Cờ Tướng" linking to `/`, the 4 items, responsive (a simple horizontal bar that still fits on a narrow mobile viewport — doesn't need a hamburger menu for MVP unless you think it's trivially easy to add, your call).

### Landing page (`apps/web/app/page.tsx`)

Per `docs/spec/v1.0/02_UX_Flows_Sitemap.md` §2.1: logo, a primary CTA **"Chơi ngay"** linking to `/play`, secondary CTAs **"Chơi với bạn"** and **"Đấu AI"** (also linking to `/play` for now, since mode-specific routing is T2.4's job — these can all point at `/play` until that task differentiates them), a short tagline. Use the `Button` component from `apps/web/components/ui/button.tsx` (T0.4) for the CTAs.

### Shared UX state components (`apps/web/src/components/states/`)

Four small, reusable components, per `docs/spec/v1.0/02_UX_Flows_Sitemap.md` §4 ("UX states bắt buộc"):
- `LoadingState.tsx`: a simple skeleton/spinner with an optional message prop.
- `EmptyState.tsx`: an icon/illustration-free simple message + optional action button, for "nothing here yet" situations (e.g. an empty move history, no saved games).
- `ErrorState.tsx`: a message + optional retry button, for a failed data fetch.
- `OfflineBanner.tsx`: a persistent small banner/bar for "mất kết nối" (connection lost) — this one is a bit special since it should actually react to the browser's online/offline status; use the `online`/`offline` window events (wrap in a `useEffect`, handle SSR gracefully — default to "online" on the server, correct itself on the client after mount) rather than requiring a prop from every caller.

Keep all four generic/reusable — no game-specific logic, just presentational components with a message/action prop and (for `OfflineBanner`) its own online-status detection.

## Required tests

- Landing page: renders the 3 CTAs and the nav (if nav is in the same render tree via layout — if testing `page.tsx` in isolation doesn't include the layout, that's fine, just test what's actually rendered by `page.tsx` itself, and separately test `NavBar` renders its 4 links with the right hrefs).
- `LoadingState`/`EmptyState`/`ErrorState`: render with and without their optional action, calling the right callback on click.
- `OfflineBanner`: renders nothing (or a neutral state) by default in the jsdom test environment; verify it responds to a simulated `window.dispatchEvent(new Event('offline'))` / `'online'` by checking its rendered output changes accordingly.
