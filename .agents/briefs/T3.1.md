# Brief: T3.1 — `shared-contracts`: Zod schemas for the whole API/socket surface

## Goal

Build `packages/shared-contracts`'s real content (currently a T0.2 placeholder): the Zod runtime schemas + derived TypeScript types that `apps/api`, `apps/web`, and `packages/api-client` will all import, for REST request/response bodies, Socket.IO event payloads, and the core domain value types that cross a network boundary (as opposed to `@xq/xiangqi-core`'s own types, which are for in-process use — this package's job is validating untrusted input and giving both client and server one shared source of truth for wire shapes). This is the most foundational task in M3/M4 — almost everything else imports from here.

## Acceptance-criteria IDs

None directly (infra enabler for ROOM-01/02, SYNC-01/02/03, CLOCK-01, DATA-01 in later tasks).

## Allowed paths

- `packages/shared-contracts/src/**` (replace the T0.2 placeholder content)
- `packages/shared-contracts/package.json` (add the `zod` dependency only, if not already present)

## Forbidden

- Do not implement any actual REST handler, Socket.IO gateway, or database schema — this package only defines shapes/validators. Those are later tasks (T3.2+, T4.2+).
- Do not duplicate `@xq/xiangqi-core`'s own internal types for in-process use — only define schemas for things that cross a wire (client↔server). You MAY import `@xq/xiangqi-core` as a `workspace:*` dependency for reference/reuse where genuinely helpful (e.g. its `ResultReason` union, to keep the Zod enum's values in sync — but Zod needs an explicit literal list, it can't validate against a TS union directly, so you'll still need to write out the enum values; just make sure they match exactly).

## Required schemas and types

Organize however's clean (e.g. `src/domain.ts`, `src/rest.ts`, `src/sockets.ts`, `src/errors.ts`, barrel-exported from `src/index.ts`) — your call, but keep it navigable since T3.2-T3.9, T4.1-T4.8, and the web app will all import from here constantly.

### Domain value types (Zod schemas + inferred types)

- `squareSchema`: a string matching `/^[a-i][0-9]$/` (ADR-018's convention — re-derive the exact regex from `docs/adr/ADR-018-coordinates-fen-uci.md`, don't guess).
- `moveSchema`: `{ from: Square, to: Square }`.
- `colorSchema`: `z.enum(['red', 'black'])`.
- `timeControlSchema`: `{ initialMs: number (positive int), incrementMs: number (non-negative int) }` — per ADR-019's presets (5+3/10+5/15+10 minutes+seconds, converted to ms).
- `clockStateSchema`: `{ redRemainingMs: number, blackRemainingMs: number, activeColor: Color, turnStartedAt: number }` (epoch ms — server clock is authoritative, per ADR-019; `turnStartedAt` is when the CURRENT turn began, used by the client to compute elapsed-since-sync for display).
- `resultReasonSchema`: a `z.enum([...])` with EXACTLY these 12 values, copied verbatim from `packages/xiangqi-core/src/game.ts`'s `ResultReason` union — open that file and copy the literal list, do not retype from memory: `CHECKMATE, STALEMATE, PERPETUAL_CHECK, REPETITION, MOVE_LIMIT, INSUFFICIENT_MATERIAL, RESIGNATION, DRAW_AGREEMENT, TIMEOUT, TIMEOUT_INSUFFICIENT_MATERIAL, ABANDONMENT, ABORTED`.
- `gameResultSchema`: `{ winner: Color | null, reason: ResultReason }`.
- `rejectReasonSchema`: `z.enum(['VERSION_CONFLICT', 'NOT_YOUR_TURN', 'ILLEGAL_MOVE', 'GAME_NOT_ACTIVE', 'NOT_A_PLAYER', 'TIME_EXPIRED', 'MOVE_ID_CONFLICT', 'RATE_LIMITED'])` — the reasons a submitted move can be rejected (used by `game:move:rejected` and the REST move-submission error path, M4).
- `gameStatusSchema`: `z.enum(['WAITING', 'ACTIVE', 'FINISHED', 'ABORTED'])` (a game's lifecycle; distinct from its eventual `GameResult`, which records WHY it finished).
- `userSummarySchema`: `{ id: string, nickname: string, type: z.enum(['guest', 'registered']) }`.

### Game/room snapshots (what a full `GET`/`game:state`/`room:state` payload looks like)

- `gameSnapshotSchema`: `{ gameId: string, status: GameStatus, initialFen: string, moves: string[] (UCI strings), gameVersion: number (non-negative int), clocks: ClockState | null (null for untimed local/AI games, present for online), result: GameResult | null, redPlayerId: string | null, blackPlayerId: string | null, serverNow: number (epoch ms — lets the client compute its clock-offset from the server on every sync, per ADR-019) }`.
- `roomMemberSchema`: `{ userId: string, nickname: string, color: Color | null, isHost: boolean }`.
- `roomSnapshotSchema`: `{ roomId: string, code: string (the human-shareable join code), status: z.enum(['WAITING', 'READY', 'STARTED', 'CLOSED']), timeControl: TimeControl, members: RoomMember[], gameId: string | null }`.

### REST request/response bodies

Define a Zod schema for the REQUEST body (where one exists) and the RESPONSE body for each of these P0 endpoints (reference `docs/spec/v1.0/03_Technical_Architecture.md` §7 for the endpoint list, but note some request/response shapes there are sketches — use the snapshot types above as the actual response shapes, not a redefinition):

| Method | Path | Request body | Response body |
|---|---|---|---|
| POST | `/sessions/guest` | `{ nickname: string (1-30 chars) }` | `UserSummary` |
| GET | `/me` | — | `UserSummary` |
| PATCH | `/me` | `{ nickname: string }` | `UserSummary` |
| POST | `/rooms` | `{ timeControl: TimeControl, hostColor: z.enum(['red','black','random']) }` | `RoomSnapshot` |
| POST | `/rooms/:code/join` | `{ nickname?: string }` | `RoomSnapshot` |
| GET | `/rooms/:code` | — | `RoomSnapshot` |
| GET | `/games/:id` | — | `GameSnapshot` |
| GET | `/games/:id/moves` | query `{ cursor?: string, limit?: number }` | `{ moves: { ply: number, uci: string, clockAfterMs: number | null }[], nextCursor: string | null }` |
| POST | `/games/:id/resign` | — | `GameSnapshot` |
| POST | `/games/:id/draw-offer` | `{ action: z.enum(['offer','accept','decline']) }` | `GameSnapshot` |

Lessons/puzzles REST contracts are OUT OF SCOPE here — those are defined later, in M6, alongside the content package itself.

### Socket.IO event maps

Define TWO interfaces (plain TS, not Zod, since these are compile-time-only type maps for the Socket.IO server/client generics — but DO define Zod schemas for each event's PAYLOAD so the gateway can runtime-validate inbound client events, per `apps/api`'s general convention of validating all untrusted input):

```ts
interface ClientToServerEvents {
  'room:join': (payload: { roomId: string }) => void;
  'game:join': (payload: { gameId: string }) => void;
  'game:move': (payload: { gameId: string; moveId: string; expectedVersion: number; move: Move }) => void;
  'game:sync': (payload: { gameId: string }) => void;
  'game:resign': (payload: { gameId: string }) => void;
  'game:draw': (payload: { gameId: string; action: 'offer' | 'accept' | 'decline' }) => void;
  'game:claim-win': (payload: { gameId: string }) => void;
}
interface ServerToClientEvents {
  'room:state': (snapshot: RoomSnapshot) => void;
  'game:move:accepted': (payload: { move: Move; moveId: string; gameVersion: number; clocks: ClockState | null }) => void;
  'game:move:rejected': (payload: { moveId: string; reason: RejectReason; authoritativeVersion: number }) => void;
  'game:state': (snapshot: GameSnapshot) => void;
  'game:finished': (payload: { result: GameResult; finalVersion: number }) => void;
}
```
Export a Zod schema per CLIENT-TO-SERVER event payload (e.g. `gameMoveEventSchema`) — server-to-client payloads don't need runtime validation (the server controls what it sends) but keep their types exported too for `api-client` to consume.

### Error envelope

```ts
interface ApiError {
  readonly error: { readonly code: string; readonly message: string; readonly details?: unknown };
}
```
Plus a small helper `isApiError(value: unknown): value is ApiError` if that's convenient, or skip it if it doesn't add value — your call.

## Required tests

For every Zod schema: at least one test asserting a valid example parses successfully, and at least one test asserting an invalid example (wrong type, out-of-range, malformed square string, etc.) is rejected. You don't need exhaustive coverage of every field combination — one clear valid/invalid pair per schema is the bar. Pay special attention to `squareSchema` (test a few invalid strings like `'j0'`, `'a10'`, `''`) since it's reused everywhere.
