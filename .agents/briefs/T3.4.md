# Brief: T3.4 — Pure game aggregate: clock math + move-command processing

## Goal

Build the pure, framework-free decision logic for "what happens when a move command arrives": clock accounting per ADR-019, and the accepted/rejected/duplicate outcome for a submitted move against the current in-memory game state. **No database, no NestJS, no `Date.now()` anywhere** — every time-dependent function takes `now: number` (epoch ms) as an explicit parameter, so tests can simulate any timeline exactly. T3.5 (a later task) wraps this pure logic in a transactional, DB-backed service; this task is the part that's cheap to test exhaustively because it has zero I/O.

## Acceptance-criteria IDs

CLOCK-01, SYNC-02 (the logic side — DB-level idempotency/locking is T3.5)

## Allowed paths

- `apps/api/src/modules/games/domain/**` (new — e.g. `clock.ts`, `game-aggregate.ts`, and their test files)

## Forbidden

- Do not import `@nestjs/*`, `@prisma/*`, or anything DB-related. Do not call `Date.now()` — every function that needs "now" takes it as a parameter.
- Do not implement any REST/Socket.IO handler, repository, or transaction — that's T3.5/T4.2.

## Read first

`docs/adr/ADR-019-clock-disconnect-policy.md` in full (clock rules), and `packages/xiangqi-core`'s `isLegalMove`/`applyMove`/`evaluateGame`/`CASUAL_RULESET` (you'll call these directly — `@xq/xiangqi-core` is already a workspace dependency of `apps/api` from T0.3). Also skim `packages/shared-contracts/src/domain.ts` (T3.1) for `RejectReason`, `Color`, `ClockState`, `TimeControl` — reuse those types/schemas rather than redefining them.

## Part 1: `clock.ts`

```ts
import type { ClockState, Color, TimeControl } from '@xq/shared-contracts';

export function createClockState(timeControl: TimeControl, now: number): ClockState;
// Both sides start at timeControl.initialMs, activeColor 'red', turnStartedAt = now.

export function remainingMsAt(state: ClockState, now: number): { red: number; black: number };
// Read-only: the CURRENT remaining time for both sides as of `now`, accounting for
// elapsed time on whichever color is active (does not mutate/advance turnStartedAt —
// for display/polling without committing a state change).

export function applyMoveToClock(
  state: ClockState,
  timeControl: TimeControl,
  now: number,
  isMoverFirstMoveOfGame: boolean,
): ClockState;
// Called exactly when a move is ACCEPTED at time `now`, for the color that is
// state.activeColor (the mover). Per ADR-019: each side's very FIRST move in the
// game is untimed (no deduction) — pass `isMoverFirstMoveOfGame = true` for that
// case and skip the deduction, but still add `timeControl.incrementMs` and flip
// `activeColor`/reset `turnStartedAt` to `now` as normal. For every other move,
// deduct `now - state.turnStartedAt` from the mover's remaining time, then add
// the increment, then flip/reset as above.

export function isFirstMoveTimedOut(turnStartedAt: number, now: number): boolean;
// ADR-019's 60-second limit on each side's untimed first move: true if
// `now - turnStartedAt > 60_000`. The caller is responsible for knowing whether
// this check even applies (i.e. that this IS one of the two first moves).

export function isClockExpired(state: ClockState, now: number): Color | null;
// Returns the color whose remaining time (per `remainingMsAt`) has hit zero or
// below, or null if neither has. Only meaningful for moves that are NOT a
// first-of-game move (use `isFirstMoveTimedOut` for those instead).
```

### Required tests (`clock.test.ts`) — exhaustive, this is cheap since everything is pure

- `createClockState`: both sides start at `initialMs`, `activeColor: 'red'`.
- `remainingMsAt`: with `activeColor: 'red'`, time passing reduces ONLY red's computed remaining, never black's; the reverse for `activeColor: 'black'`.
- `applyMoveToClock` (non-first-move): deducts exactly the elapsed time from the mover's remaining, adds the increment, flips `activeColor`, resets `turnStartedAt` to `now`.
- `applyMoveToClock` (first move, `isMoverFirstMoveOfGame: true`): remaining time is UNCHANGED (no deduction) regardless of elapsed time, increment still added, `activeColor` still flips.
- `isFirstMoveTimedOut`: true at `now - turnStartedAt > 60_000`, false at exactly 60_000 or below (pick one boundary convention — `>` not `>=`, or document if you choose otherwise — be consistent and explicit).
- `isClockExpired`: returns the correct color when its remaining hits ≤0, `null` when both have time left, and correctly reflects only the ACTIVE color's depletion (the inactive color's remaining doesn't change just from time passing).

## Part 2: `game-aggregate.ts`

```ts
import type { Color, Move, Position, Square } from '@xq/xiangqi-core';
import type { ClockState, RejectReason, TimeControl } from '@xq/shared-contracts';
import type { GameResult } from '@xq/xiangqi-core';

export interface GameAggregateState {
  readonly status: 'WAITING' | 'ACTIVE' | 'FINISHED' | 'ABORTED';
  readonly initialFen: string;
  readonly position: Position;          // current position, kept in sync with `moves`
  readonly moves: readonly Move[];
  readonly moveIds: readonly string[];  // parallel to `moves` — the client-supplied idempotency key for each
  readonly gameVersion: number;         // increments by 1 per accepted move
  readonly timeControl: TimeControl | null; // null for untimed (local/AI) games
  readonly clock: ClockState | null;        // null iff timeControl is null
  readonly result: GameResult | null;
}

export interface SubmitMoveCommand {
  readonly color: Color;       // which color the submitter claims to be playing
  readonly moveId: string;
  readonly expectedVersion: number;
  readonly move: Move;
}

export type SubmitMoveOutcome =
  | { readonly type: 'accepted'; readonly state: GameAggregateState }
  | { readonly type: 'duplicate'; readonly state: GameAggregateState } // resend of the most-recently-accepted moveId — state is unchanged, caller re-sends the same accepted response instead of reprocessing
  | { readonly type: 'rejected'; readonly reason: RejectReason };

export function createGameAggregate(initialFen: string, timeControl: TimeControl | null, now: number): GameAggregateState;
// status starts 'WAITING'; a separate concern (T3.6/T4.2) transitions it to 'ACTIVE'
// once both seats are filled — this function doesn't know about seats/rooms.

export function submitMove(state: GameAggregateState, command: SubmitMoveCommand, now: number): SubmitMoveOutcome;
```

### `submitMove` algorithm (implement exactly this order)

1. **Duplicate check first, before anything else**: if `command.moveId` equals the LAST entry of `state.moveIds` (i.e. this is a resend of the most recently accepted move), return `{ type: 'duplicate', state }` unchanged — this must short-circuit before version/turn/legality checks, since a legitimate retried request will naturally have a now-stale `expectedVersion` from the mover's point of view.
2. If `state.status !== 'ACTIVE'`: reject `GAME_NOT_ACTIVE`.
3. If `command.expectedVersion !== state.gameVersion`: reject `VERSION_CONFLICT`.
4. If `command.color !== state.position.turn`: reject `NOT_YOUR_TURN`.
5. If `!isLegalMove(state.position, command.move)` (from `@xq/xiangqi-core`): reject `ILLEGAL_MOVE`.
6. **Clock check** (only if `state.timeControl`/`state.clock` are non-null): determine if this is `command.color`'s first move of the game (i.e. `state.moves` contains no prior move by `command.color` — you can determine this by checking whether `state.moves.length < 2`, since Red moves on even indices (0, 2, 4...) and Black on odd (1, 3, 5...) — Red's first move is index 0 if it exists, i.e. `state.moves.length === 0`; Black's first move is index 1, i.e. `state.moves.length === 1`; so "is this mover's first move" is simply `state.moves.length === 0 || state.moves.length === 1`). If it IS a first move: reject `TIME_EXPIRED` if `isFirstMoveTimedOut(state.clock.turnStartedAt, now)`. If it's NOT a first move: reject `TIME_EXPIRED` if `isClockExpired(state.clock, now) === command.color`.
7. **Apply**: `position = applyMove(state.position, command.move)`; `moves = [...state.moves, command.move]`; `moveIds = [...state.moveIds, command.moveId]`; `gameVersion = state.gameVersion + 1`; `clock = state.clock === null ? null : applyMoveToClock(state.clock, state.timeControl!, now, <was-first-move-from-step-6>)`; `result = evaluateGame({ initialFen: state.initialFen, moves, ruleSetVersion: CASUAL_RULESET.version }, CASUAL_RULESET)` (no `terminalEvent` — resignation/timeout/abandonment/abort are handled by OTHER commands in later tasks, not by `submitMove`); `status = result === null ? 'ACTIVE' : 'FINISHED'`. Return `{ type: 'accepted', state: <the new state> }`.

### Required tests (`game-aggregate.test.ts`)

- A full legal move sequence: `gameVersion` increments by exactly 1 per accepted move, `position`/`moves`/`moveIds` stay consistent.
- `VERSION_CONFLICT`: submitting with a stale `expectedVersion` after a move was already accepted.
- `NOT_YOUR_TURN`: submitting with the wrong `color`.
- `ILLEGAL_MOVE`: submitting a move that isn't in `getLegalMoves` for the current position.
- `GAME_NOT_ACTIVE`: submitting against a `WAITING`/`FINISHED`/`ABORTED` aggregate.
- **Duplicate/idempotency**: submit a move, then resubmit the EXACT same `{moveId, expectedVersion, move, color}` again — second call returns `{ type: 'duplicate' }` with the state unchanged (not reprocessed, not rejected).
- Clock: a timed aggregate where a non-first move arrives after its side's remaining time has elapsed → `TIME_EXPIRED`; a first move arriving after 61 simulated seconds → `TIME_EXPIRED` via the first-move path specifically (construct this with fake timestamps, not real waiting).
- A move that results in checkmate sets `status: 'FINISHED'` and a non-null `result` with the correct winner.
- An untimed aggregate (`timeControl: null`) never rejects for `TIME_EXPIRED` regardless of simulated elapsed time, and `clock` stays `null` throughout.
