# Brief: T4.1 — `createGameSocket()`: typed Socket.IO client wrapper

## Goal

A thin, typed wrapper around `socket.io-client` in `packages/api-client`, matching the `ClientToServerEvents`/`ServerToClientEvents` maps already defined in `packages/shared-contracts/src/sockets.ts` (T3.1). This is the ONLY place `apps/web` will ever touch `socket.io-client` directly — later, T4.4's `OnlineGameController` builds the actual game-sync/reconnect LOGIC on top of this primitive; this task is just the typed transport.

## Acceptance-criteria IDs

None directly (infra enabler for SYNC-01..03 via T4.4).

## Allowed paths

- `packages/api-client/src/socket.ts` (new — keep it separate from T3.9's REST client code in `index.ts`, re-export from `index.ts`'s barrel)
- `packages/api-client/src/socket.test.ts` (new)
- `packages/api-client/package.json` (add `socket.io-client`)

## Forbidden

- Do not add reconnect/resync GAME LOGIC here (e.g. "call sync on reconnect") — that's T4.4's job, built in `apps/web` on top of what this task exposes. This task only wraps the raw socket connection/events typedly.
- Do not modify `packages/api-client/src/index.ts`'s existing REST client code (T3.9) beyond adding a re-export line for whatever this task exports.

## Design

```ts
import type {
  ClientToServerEvents, ServerToClientEvents,
} from '@xq/shared-contracts';

export interface GameSocketHandlers {
  onConnect?: () => void;
  onDisconnect?: (reason: string) => void;
  onRoomState?: (payload: ServerToClientEvents['room:state'] extends (p: infer P) => void ? P : never) => void;
  onGameState?: (payload: /* same extraction pattern */) => void;
  onMoveAccepted?: (payload: /* ... */) => void;
  onMoveRejected?: (payload: /* ... */) => void;
  onGameFinished?: (payload: /* ... */) => void;
}

export interface GameSocket {
  joinRoom(roomId: string): void;
  joinGame(gameId: string): void;
  submitMove(payload: { gameId: string; moveId: string; expectedVersion: number; move: { from: string; to: string } }): void;
  sync(gameId: string): void;
  resign(gameId: string): void;
  draw(gameId: string, action: 'offer' | 'accept' | 'decline'): void;
  claimWin(gameId: string): void;
  disconnect(): void;
  readonly connected: boolean;
}

export function createGameSocket(baseUrl: string, handlers: GameSocketHandlers): GameSocket;
```
(The exact TS mechanics for extracting each event's payload type from `ServerToClientEvents`/`ClientToServerEvents` — whether via the conditional-type pattern sketched above, a small local type helper, or just writing out the payload types directly inline — is your call; the point is the handler/method signatures must be type-safe against T3.1's event maps, not loosely typed as `any`/`unknown`.)

Implementation: `io(baseUrl, { withCredentials: true, autoConnect: true })` — `withCredentials: true` is required so the `xq_sid` session cookie (T3.3) actually accompanies the Socket.IO handshake (needed by T4.2's server-side auth). Wire each `ServerToClientEvents` key to call the matching handler if provided (no-op if not). Expose `joinRoom`/`joinGame`/`submitMove`/`sync`/`resign`/`draw`/`claimWin` as thin `socket.emit('event:name', payload)` calls using the EXACT event names from `packages/shared-contracts/src/sockets.ts` — don't invent different names. Default Socket.IO reconnection behavior (its built-in exponential backoff) is fine — don't disable it and don't hand-roll your own reconnect loop, that's explicitly out of scope here.

## Required tests

Mock `socket.io-client`'s `io()` (e.g. `vi.mock('socket.io-client', ...)` returning a fake socket object with `emit`/`on`/`disconnect`/`connected` you control) — don't spin up a real server for this unit-level test (that's T4.8's E2E job).
- `createGameSocket` calls `io()` with `withCredentials: true`.
- Each outbound method (`joinRoom`, `submitMove`, etc.) calls `socket.emit` with the correct event name and payload shape.
- Registering handlers actually wires to the mocked socket's `on(...)` calls, and invoking the mocked event triggers the right handler with the right payload.
- `disconnect()` calls through to the mock socket's `disconnect`.
