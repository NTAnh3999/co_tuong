# Brief: T6.6 — `/learn` + `/learn/[slug]` lesson renderer

## Goal

`/learn` lists the lesson summaries T6.7's `GET /lessons` serves (now backed by T6.3's 10 real Vietnamese lessons); `/learn/[slug]` renders one lesson's steps, letting the learner move forward/back through them with the board and caption updating together.

## Read first

- `packages/content/src/schema.ts`'s `lessonSchema` and `packages/shared-contracts/src/domain.ts`'s `lessonSummarySchema`/`lessonDetailSchema`/`lessonStepSchema` — a lesson detail is `{ slug, title, level, steps: [{ fen, caption, highlightSquares }] }`. Look at a couple of the real files under `packages/content/data/lessons/*.json` (T6.3's work) to see what real content actually looks like, not just the schema shape.
- `packages/api-client/src/index.ts`'s `getLessons()`/`getLesson(slug)` methods (already added in T6.7) — the two calls this feature needs.
- `apps/web/app/history/page.tsx` and `apps/web/app/history/[id]/page.tsx` (T6.8, just landed) — the closest existing analog for BOTH pages you're building: a list page that fetches a summary array and links into a detail page, and a detail page that steps through an array of positions with a stepper UI and a read-only `Board2D`. Your `/learn/[slug]` page is structurally very similar to `/history/[id]` (step forward/back through precomputed states) — reuse that UI pattern rather than inventing a new one, though it's a DIFFERENT controller (a lesson step is `{fen, caption, highlightSquares}`, not a replayed move — there's no `replay()` call here, each step's `fen` is already a complete position given directly by the content, decoded with `fromFen`).
- `apps/web/src/features/game/board/Board2D.tsx`'s props, specifically `selectedSquare: Square | null` and `legalTargets: readonly Square[]` — both are just visual highlight hooks from the board's perspective (rendered as highlight markers), not functionally tied to "legal moves." You can reuse `legalTargets` to visually mark a step's `highlightSquares` even though this isn't a move-legality context — it's a reasonable reuse of the existing visual, not a hack that breaks anything. If you find this visually confusing once you see it rendered, it's also fine to skip visual highlighting and rely on the caption text alone — note which you chose in KNOWN GAPS.
- This feature does NOT need `@xq/xiangqi-core`'s `replay()` — unlike `/history/[id]`, consecutive lesson steps are independent authored positions, not a move sequence. Each step's board state comes directly from `fromFen(step.fen)`.

## Design

### `/learn` page

- `useSession()` is NOT required here — unlike puzzles/history, lesson content isn't user-specific, so `GET /lessons` doesn't need authentication context to decide WHAT to show (though the endpoint itself is still behind `SessionGuard` server-side, so you do need a resolved session to call it — use `useSession()` only to gate the API call, the same loading/error pattern every other page uses, not to vary the content shown).
- `apiClient.getLessons()` once on mount. Render a list grouped or at least visibly labeled by `level` (beginner/intermediate/advanced — translate to Vietnamese labels: "Cơ bản" / "Trung bình" / "Nâng cao" or similar), each linking to `/learn/<slug>`.
- Loading/error/empty states via the existing `LoadingState`/`ErrorState` components.

### `/learn/[slug]` page

- `params: Promise<{ slug: string }>` (Next 15 convention, same as `/history/[id]` and `/game/[id]`).
- `apiClient.getLesson(slug)` once on mount → a `LessonDetail` with its `steps` array.
- Local `currentStep` state (0-indexed, clamped to `[0, steps.length - 1]`), with previous/next buttons (and/or a numbered-step list to jump directly, same "jump to any step" idea `/history/[id]` offers for plies).
- Render `Board2D` with `interactive={false}`, `position={fromFen(steps[currentStep].fen)}`, `selectedSquare={null}`, `legalTargets={steps[currentStep].highlightSquares}` (if you chose to visualize them) or `[]` (if you chose caption-only), `lastMove={null}`, a fixed orientation (`'red'` is fine).
- Show the current step's `caption` prominently next to the board.
- A 404-equivalent state if `getLesson` fails (missing slug) — reuse `ErrorState`, no need for a styled 404 page.

## Required tests

- `learn/page.test.tsx`: renders a list from a mocked `getLessons()`, grouped/labeled by level, each row linking to the correct `/learn/<slug>`, and a loading/error state before/if the call fails.
- `learn/[slug]/page.test.tsx`: given a mocked `getLesson()` response with at least 3 steps, stepping forward/back updates the rendered caption AND the board's position to match `fromFen(steps[i].fen)` for the step actually being shown — assert the real position object, not just that some text changed. A failed `getLesson()` call shows an error state.
