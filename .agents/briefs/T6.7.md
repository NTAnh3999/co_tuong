### `ContentController`

```ts
@Controller()
@UseGuards(SessionGuard)
export class ContentController {
  @Get('lessons') getLessons(): Promise<LessonSummary[]>
  @Get('lessons/:slug') getLesson(@Param('slug') slug: string): Promise<LessonDetail>  // 404 if not found
  @Get('puzzles') getPuzzles(): Promise<PuzzleSummary[]>
  @Get('puzzles/:id') getPuzzle(@Param('id') id: string): Promise<PuzzleDetail>  // 404 if not found
  @Post('puzzles/:id/attempts') recordAttempt(@Param('id') id, @CurrentUser() user, @Body() body): Promise<{status, attempts}>
}
```

`recordAttempt`: upsert `LearningProgress` keyed on `(userId, contentType: 'PUZZLE', contentId: id)` — increment `attempts` by 1 each call, set `status: 'COMPLETED'` and `completedAt: now()` if `body.completed` is true (and it wasn't already completed — don't overwrite an existing `completedAt` on a later non-completing attempt), else `status: 'IN_PROGRESS'`. Return the row's current `status`/`attempts`.

Field mapping from Prisma rows to the response schemas: `level`/`sideToMove` need lowercasing (`'BEGINNER'` → `'beginner'`, `'RED'` → `'red'`), `bodyJson`/`solutionJson`/`allowedAlternatives`/`hints` are stored as `Json` columns — cast/validate them back to the typed shape when reading (a `z.array(...).parse(row.solutionJson)` or similar, so a corrupted/legacy row fails loudly rather than silently serving malformed data to a client).
