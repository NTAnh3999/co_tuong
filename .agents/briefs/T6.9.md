# Brief: T6.9 — `/profile` page

## Goal

A small page where the current user can view/edit their nickname and jump into their recent games. Every API piece it needs already exists — this is a page-assembly task, not new backend work.

## Acceptance-criteria IDs

— (none listed in `.agents/PLAN.md` for this task)

## Read first

- `apps/web/src/features/session/use-session.ts` — `useSession()`, the hook every authenticated page uses to get `{ user, status }`.
- `packages/api-client/src/index.ts`'s `updateMe(payload: { nickname: string })` and `getMyGames()` methods (both already exist — `updateMe` since early M1/M3 work, `getMyGames` added in T6.7).
- `apps/web/app/play/online/page.tsx` or `apps/web/app/play/ai/page.tsx` — for the `useSession()` + loading/error-state + simple-form conventions this page should match (a small controlled form with a submit handler, inline error state, `Button`/`LoadingState`/`ErrorState` from the existing shared components — don't invent new primitives).
- `packages/shared-contracts/src/rest.ts`'s `getMyGamesResponseSchema`/`GetMyGamesResponse` shape (`{ games: [{ gameId, opponent: {id, nickname} | null, status, result }] }`) — what you'll render for the "recent games" shortcut.

## Design

- `useSession()` for the current user; show `LoadingState`/`ErrorState` the same way other pages do while it resolves.
- A nickname-edit form: an input pre-filled with `user.nickname`, a submit button that calls `apiClient.updateMe({ nickname })`. On success, show a brief confirmation and reflect the new nickname in the input (don't require a page reload). On failure, show an inline error and leave the input as the user typed it (don't silently revert).
- A "recent games" section: on mount, call `apiClient.getMyGames()`. Show up to, say, the first 5 entries (your call on the exact number — there's no pagination on this endpoint, it returns everything, so just slice client-side) as a short list, each linking to `/history/<gameId>`, with a "Xem tất cả" (view all) link to `/history`. If the list is empty, show a plain friendly message, not an error.
- Keep this page simple — no new shared components, no new API methods. If you find yourself wanting one, it's a sign you're overbuilding; stop and reconsider within the existing pieces first.

## Required tests

`apps/web/app/profile/page.test.tsx`, same style as other page tests in this app (mock `apiClient`, mock `useSession`):
- Renders the current nickname pre-filled in the form once the session resolves.
- Submitting a new nickname calls `apiClient.updateMe({ nickname: <new value> })` and shows a success indication.
- A failed `updateMe` call shows an inline error without clearing the input.
- Renders recent games from a mocked `getMyGames()`, each linking to the correct `/history/<gameId>` path, and an empty list shows a friendly empty state rather than an error.
