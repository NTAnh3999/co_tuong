# Brief: T7.6 — `/rules`, `/privacy`, `/terms`, `/licenses`

## Goal

Four static content pages, in Vietnamese (user-facing copy), reachable from a small shared footer: a casual-play rules disclaimer, a privacy notice, terms of use, and a licenses page (this one is NOT optional boilerplate — it must correctly disclose the Pikafish engine's GPLv3 license and the separate NNUE network license, per this project's own AGENTS.md rule and ADR risk-mapping around "GPLv3 exposure").

## Read first

- `docs/adr/ADR-017-ruleset-casual-v1.md` — the actual ruleset this project implements (no-legal-moves is always a loss, never a stalemate draw; perpetual CHECK is implemented and penalizes the checking side on a 3rd repeat; perpetual CHASE of a non-check piece is explicitly NOT implemented and such a repeat is just an ordinary draw). `/rules` must describe these two repetition rules correctly and distinctly — do not conflate them (a previous task this project ran, T6.3, caught a real mistake here; read the ADR yourself rather than trusting a paraphrase).
- `tools/pikafish/Copying.txt` and `tools/pikafish/NNUE-License.md` — read both in full. `/licenses` must state: the engine binary is Pikafish, licensed under GPLv3 (link/name the license, don't just say "open source"), used server-side only and unmodified; the NNUE evaluation network has its own separate license (read `NNUE-License.md` to state what it actually says, don't guess); and that source/build instructions for Pikafish are available per GPLv3's requirements (state where — e.g. a link to the upstream Pikafish repository; if you don't know the exact upstream URL, reference `tools/pikafish/README.md` or `AUTHORS`/`Top CPU Contributors.txt` for attribution and say in KNOWN GAPS that the exact upstream link should be confirmed before this goes live, rather than fabricating one).
- `apps/web/app/learn/page.tsx` — the simplest existing page pattern in this codebase (static-ish list rendering, Tailwind utility classes, `<main className="mx-auto ...">` wrapper convention) — follow this visual/structural convention; these four pages don't need `useSession()` or any API call at all, they're fully static.
- `apps/web/src/components/shell/NavBar.tsx` and `apps/web/app/layout.tsx` — see how the root layout composes `NavBar` today. There is currently no footer component.

## Design

### `Footer`

- A simple `<footer>` with links to the four new pages, rendered in Vietnamese: "Luật chơi" (`/rules`), "Quyền riêng tư" (`/privacy`), "Điều khoản" (`/terms`), "Giấy phép" (`/licenses`). Composed into `layout.tsx` once, globally, below the page content (same place any app-wide chrome belongs).

### The four pages

- Each is a plain server-renderable static page (no `'use client'` needed unless you have a concrete reason) with a heading and body copy, written in Vietnamese, using the same `<main className="mx-auto flex min-h-screen w-full max-w-3xl flex-col gap-6 px-4 py-10">`-style wrapper the rest of the app uses.
- `/rules`: casual-play disclaimer — state plainly that this implements a casual ruleset (ADR-017), not an official competition ruleset; describe no-legal-moves-is-loss and both repetition rules correctly and distinctly as read above.
- `/privacy`: what data is collected (accounts/nicknames, game history, guest sessions), that this is a learning/casual platform not a commercial one (your call on exact wording — keep it honest and simple, don't invent compliance claims like GDPR/CCPA certification that aren't backed by anything in this codebase).
- `/terms`: basic terms of use — casual/educational use, no warranty, account/guest session behavior.
- `/licenses`: the Pikafish GPLv3 + NNUE license disclosure described above, plus a line noting the project's own open-source dependencies are listed in its `package.json` files (don't attempt to enumerate every npm dependency by hand here — that's a maintenance trap; a one-line pointer is enough).

## Required tests

- `Footer.test.tsx`: renders all four links with the correct Vietnamese labels and `href`s.
- For each of the four pages, at minimum a smoke test asserting the page renders its main heading (`screen.getByRole('heading', ...)`) — these are static pages, so an exhaustive content test isn't needed, but each page must be proven to render without throwing.
